# Herramientas de arquitectura contractual

ECO-M6 mantiene en `validation-history.mjs` una vista pura de diez valores exactos de metadata/CI, entradas de registro y pruebas H1A v2 hacia la base e80, sin reconstruir validaciones históricas. El scope relee hashes de veinte rutas por invocación, incluidos módulo/test de admisión; nunca conserva aprobaciones del checkout. Rechaza metadata parcial o alterada tanto con planned M6 como con raíces seleccionadas. El contexto síncrono Finance conserva sus límites y negativos. La vista fuente de `scripts/identity/internal-auth-v2-admission.mjs` permite al gate candidato preservar su snapshot histórico; el gate de admisión valida por separado las cuatro raíces actuales, cierres/consumidores y procedencia, sin conceder consumo runtime. Tests externos de historia y admisión cubren exactitud, retorno aislado, drift/omisión tras calentamiento y lecturas 1/10/100 sin otro archivo vivo por proyección. Inventory selecciona la admisión histórica por ID, sin depender del orden al agregar raíces; sus negativos se conservan. Sales rechaza una política H1A alterada/ausente después de un uso válido.

- `cli.mjs`: registro, snapshots, consumidores e impacto; comandos en el README raíz.
- `graph.mjs`: cierres, selección semántica, locks e impacto. Reutiliza cierres de lectores Git nativos por repositorio/revisión, raíz, versión, selección, mappings y dominios; hasta 256 resultados y 32 MiB serializados. Devuelve valores aislados; los tags y admisiones se comprueban fuera de esa reutilización.
- `git-source.mjs`: lectura agrupada de blobs desde commits completos e inmutables. Comparte objetos por repositorio, devuelve copias y limita precarga a 16 MiB y caché de bytes a 64 MiB por proceso; cada blob conserva el límite de 8 MiB. Lo que no se precarga se lee bajo demanda.
- `consumer-gate.mjs`, `registry.mjs`, `layout.mjs` y `yaml-source.mjs`: validación de consumidores, registro, organización y parsing.
- `validation-history.mjs`: vistas históricas de valores exactos de revisiones inmutables y del delta declarado de herramientas. Solo proyecta hacia ancestros, sin promover fixtures antiguos a estados nuevos. Las vistas de archivos, registros e índices no validan el árbol completo ni reparan entradas alteradas; sus gates públicos de preservación conservan esa responsabilidad. Los lectores encadenados reconocen valores ya históricos.
- `validation-tooling.json`: referencia revisada de huellas de herramientas. El verificador fija tanto su huella esperada como el inventario permitido; el JSON no concede rutas ni se convierte en autoridad al importarse. Cada gate relee herramientas y referencia. Para evitar circularidad, la huella del cuerpo del helper sustituye únicamente el literal del pin por un marcador; ese literal se compara por separado con el pin del verificador. Todo el contenido queda comprobado, normalizando CRLF como los guards anteriores. No guarda aprobaciones ni se regenera durante una validación.

La caché Git es solo memoria del proceso: no guarda resultados de validación ni lecturas del árbol actual, tags o lectores inyectados. No cambia contratos, versiones, pins, admisiones ni comandos CI. Cada validación de preservación sigue comprobando las fuentes actuales. Las pruebas externas de `test/architecture/git-source.test.mjs` usan Git real y ejercitan bytes binarios, procedencia, aislamiento, respuestas incompletas y rechazo de rutas inválidas.

`immutable-closure.test.mjs` verifica aislamiento, lectores mutables y tags después de reutilizar cierres. `validation-history.test.mjs` verifica trabajo acotado por lectura, composición, delta exacto y drift tras calentamiento. Las revisiones de las vistas son fuentes de datos históricos, no evidencia de publicación/CI ni aprobación del árbol actual; estas últimas siguen requiriendo sus gates y autorización.
